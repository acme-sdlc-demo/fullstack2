# frontend/lib

## What it does
This area is a single helper, `cn()`, that every styled UI component in the frontend calls to combine its Tailwind CSS class names safely — it is the one place that decides "which class wins" when a component's default classes and a caller's override classes conflict [cite: frontend/src/lib/utils.ts:4-6]. `cn()` takes any number of class-name values (`ClassValue[]` from `clsx`), lets `clsx` join and filter them (dropping `false`/`null`/`undefined`), then passes the result through `twMerge` from `tailwind-merge` so that later, more specific Tailwind utility classes replace earlier conflicting ones instead of both being applied [cite: frontend/src/lib/utils.ts:1-5]. The whole area is one file, `frontend/src/lib/utils.ts`, 6 lines long, with no other source files and no types of its own [cite: frontend/src/lib/utils.ts:1-6]. It exists because the project's UI kit is shadcn/ui, whose generator is configured to import this exact helper by the alias `@/lib/utils` for every component it scaffolds [cite: frontend/components.json:16].

## Main flows
There is one flow through this area; it repeats at every call site.
1. A component under `frontend/src/components` imports `cn` via the `@/lib/utils` alias that shadcn/ui's config points at this file [cite: frontend/components.json:16].
2. The component calls `cn(baseClasses, conditionalClasses, props.className)` — for example `Button()` composes its variant classes this way [cite: frontend/src/components/ui/button.tsx:39].
3. Inside `cn()`, `clsx(inputs)` joins the arguments into one space-separated class string, skipping any falsy entry (so a conditional like `isActive && "bg-primary"` drops out cleanly when false) [cite: frontend/src/lib/utils.ts:4-5].
4. `twMerge(...)` re-parses that string and, for each Tailwind utility "slot" (e.g. background colour, padding), keeps only the last class supplied for that slot, so a caller's `className` prop reliably overrides the component's own default instead of both ending up in the DOM [cite: frontend/src/lib/utils.ts:2,5].
5. The returned string is passed straight into the component's `className` attribute, ending the flow — there is no state, no I/O and nothing is written or read beyond this in-memory string transform [cite: frontend/src/lib/utils.ts:5-6].

## Where it's fragile
- `cn()` is the single most depended-on symbol in the whole frontend (27 files, used in more other files than any other symbol in the project, per the code graph's "most depended on" ranking) [cite: frontend/src/lib/utils.ts:4]. Any change to its name, its signature, or its merge behaviour (e.g. swapping `twMerge` for a plain `clsx` call) would visibly or subtly change class output across every `ui/*` component and several feature components at once — check a broad set of those call sites (start with `frontend/src/components/ui/button.tsx:39`, `frontend/src/components/ui/card.tsx:5`, `frontend/src/components/Common/Logo.tsx:16`) after any edit here.
- There is no dedicated test file for this helper: no `*.test.ts`/`*.spec.ts` matching `lib/utils` was found under `frontend/src/lib` [cite: frontend/src/lib/utils.ts:1-6]. Because `cn()` is pure and tiny, a regression would most likely surface as a visual/class-order difference rather than a thrown error, so it would not be caught by the gate's build or lint steps alone — treat any change to this file as needing a new unit test (e.g. asserting `cn("p-2", "p-4")` resolves to `"p-4"`) before relying on manual review.
- The version pins matter: `clsx` and `tailwind-merge` are declared as caret ranges (`^2.1.1`, `^3.7.0`) in the frontend manifest [cite: frontend/package.json:37,46]; per CLAUDE.md the install must use the committed lock file (`npm ci`/`bun ci`/etc.) rather than a fresh resolve, since a newer `tailwind-merge` major could change which class "wins" in step 4 of the flow above.

## What it connects to
- Used by area `frontend/components`: call sites of `cn()` live under `frontend/src/components`, including the generic `ui/*` kit (e.g. `frontend/src/components/ui/button.tsx:39`, `frontend/src/components/ui/card.tsx:5`) and feature components such as `frontend/src/components/Common/Logo.tsx:16` and `frontend/src/components/UserSettings/UserInformation.tsx:31`.
- Uses no other area of this codebase: the file's only imports are the two external libraries below, with no import of another path under `frontend/src` [cite: frontend/src/lib/utils.ts:1-2].
- External libraries: `clsx` 2.1.1, imported for its `ClassValue` type and the `clsx()` joiner [cite: frontend/src/lib/utils.ts:1]; `tailwind-merge` 3.7.0, imported for `twMerge()` [cite: frontend/src/lib/utils.ts:2]. Both are declared as dependencies in the frontend manifest [cite: frontend/package.json:37,46].
- No database, cache, external service, or file I/O: the function is synchronous and operates only on in-memory strings [cite: frontend/src/lib/utils.ts:4-6].
- The `@/lib/utils` import alias that every caller uses is defined by the shadcn/ui generator config, not by this file itself, so the alias's resolution (via the frontend's TypeScript path mapping) is a dependency this area relies on but does not control [cite: frontend/components.json:16].
