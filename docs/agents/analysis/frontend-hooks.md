# frontend/hooks

## What it does
This area holds four small, independent React hooks shared across the app: session/auth state and its mutations (`useAuth`), toast notifications (`useCustomToast`), clipboard copy with auto-reset feedback (`useCopyToClipboard`), and a viewport-width check for responsive layout (`useIsMobile`) [cite: frontend/src/hooks/useAuth.ts:18], [cite: frontend/src/hooks/useCustomToast.ts:3], [cite: frontend/src/hooks/useCopyToClipboard.ts:8], [cite: frontend/src/hooks/useMobile.ts:5]. None of the four hooks import each other except `useAuth`, which calls `useCustomToast` to surface login/signup errors as toasts [cite: frontend/src/hooks/useAuth.ts:12,21]. There is no shared domain model here: each hook wraps one browser or library capability (`localStorage`, `navigator.clipboard`, `window.matchMedia`, `sonner`'s `toast`) behind a small API that components and routes call directly [cite: frontend/src/hooks/useAuth.ts:14-16], [cite: frontend/src/hooks/useCopyToClipboard.ts:12,18], [cite: frontend/src/hooks/useMobile.ts:9], [cite: frontend/src/hooks/useCustomToast.ts:1].

## Main flows
1. **Login**: a route calls `useAuth()` [cite: frontend/src/hooks/useAuth.ts:18] → its `loginMutation` runs `login`, which calls `LoginService.loginAccessToken` from `frontend/client` [cite: frontend/src/hooks/useAuth.ts:41-46] → on success it writes `access_token` to `localStorage` [cite: frontend/src/hooks/useAuth.ts:45] and navigates to `/` [cite: frontend/src/hooks/useAuth.ts:50-52]; on error `handleError` (bound to `showErrorToast` from `useCustomToast`) reports it [cite: frontend/src/hooks/useAuth.ts:21,35], [cite: frontend/src/hooks/useCustomToast.ts:10-14]. Ends by writing `access_token` into browser storage.
2. **Session read**: `useAuth` runs a `useQuery` keyed `["currentUser"]` that calls `UsersService.readUserMe()`, but only `enabled: isLoggedIn()`, i.e. only when `localStorage.getItem("access_token")` is non-null [cite: frontend/src/hooks/useAuth.ts:14-16,23-27]. Ends by reading `localStorage` and, if present, the `/users/me` response into React Query's cache.
3. **Sign-up**: `signUpMutation` calls `UsersService.registerUser` [cite: frontend/src/hooks/useAuth.ts:29-31] → on success navigates to `/login` [cite: frontend/src/hooks/useAuth.ts:32-34]; `onSettled` invalidates the `["users"]` query so any user list refetches [cite: frontend/src/hooks/useAuth.ts:36-38]; errors go through the same `handleError`/`showErrorToast` path [cite: frontend/src/hooks/useAuth.ts:35], [cite: frontend/src/hooks/useCustomToast.ts:10-14].
4. **Copy-to-clipboard**: a component calls `copy(text)` returned by `useCopyToClipboard()` [cite: frontend/src/hooks/useCopyToClipboard.ts:8,11] → it calls `navigator.clipboard.writeText(text)`, stores the copied text in state, and clears it again after 2000ms via `setTimeout` [cite: frontend/src/hooks/useCopyToClipboard.ts:12,18-21]; on an unsupported browser or a thrown error it logs a warning and returns `false` without copying [cite: frontend/src/hooks/useCopyToClipboard.ts:12-15,24-28]. Ends by writing to the OS clipboard (side effect outside the DOM/app state).

## Where it's fragile
- `useAuth.ts` is the area's one hotspot (score 70, 70 lines) [cite: frontend/src/hooks/useAuth.ts:1-70] and is imported by 13 files across `frontend/components` and `frontend/routes`, so a change to its returned shape (`signUpMutation`, `loginMutation`, `logout`, `user`) or to `isLoggedIn` ripples widely; check every caller listed in the graph's "what other areas use of it" before changing the return shape or the `access_token` key name [cite: frontend/src/hooks/useAuth.ts:61-67,14-16,69].
- `isLoggedIn` and `logout` read/write the `access_token` localStorage key directly, in two different places in the same file (`isLoggedIn` at line 15, `login`'s write at line 45, `logout`'s removal at line 57); if the key name or storage mechanism ever changes, all three must change together, and nothing in this file enforces that beyond convention [cite: frontend/src/hooks/useAuth.ts:14-16,41-46,56-59].
- There are no `*.test.ts`/`*.spec.ts` files for this area found under `frontend/src/hooks` in the layout's listed test patterns, so none of these four hooks has a unit test; a change to `useCopyToClipboard`'s fallback/error paths (lines 12-15, 24-28) or to `useIsMobile`'s resize listener (lines 8-16) has no test to catch a regression — exercise them manually or via the Playwright end-to-end suite that already visits pages using `useAuth` flows [cite: frontend/src/hooks/useCopyToClipboard.ts:12-15,24-28], [cite: frontend/src/hooks/useMobile.ts:8-16].
- `useCustomToast`'s two messages ("Success!" / "Something went wrong!") are hardcoded and consumed by 11 other files' `onSuccess`/`onError` handlers; changing the wording or the `description` parameter's meaning affects every caller's toast copy at once [cite: frontend/src/hooks/useCustomToast.ts:4-14].
